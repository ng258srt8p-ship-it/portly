## Current State

### Done
1. **Auto-compaction extension patched** — Two bugs fixed in `~/.pi/agent/npm/node_modules/@capyup/pi-auto-compact/extensions/auto-compact.ts`:
   - **Bug 1 (context handler):** The `context` event handler called `updateCachedLimits(ctx)` which fell back to `ctx.model?.contextWindow ?? 200000`, defaulting to 200K. For a 131K model, this meant `cachedAutoCompactLimit = 180K`, so 133K-token prompts never triggered compaction. Fixed by using `ctx.getContextUsage().contextWindow` to detect the real 131K window.
   - **Bug 2 (pendingCompaction race):** The `!pendingCompaction` guard blocked emergency truncation entirely when a prior compaction was still async. Split the logic: always truncate when over limit; only gate *starting a new compaction* on `!pendingCompaction`.
   - **Improvement:** `session_start` handler now initializes cached limits from `getContextUsage()` for all session types (not just resume/fork).
2. **User briefed on enable/disable:** Explained `/auto-compact` TUI command, `pi config` TUI toggle, and settings.json object-form filtering (`"extensions": []`).
