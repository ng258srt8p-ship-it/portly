## Established Facts

1. **DFlash infinite reload loop root cause**: The `funnygeeker/Qwen3.6-35B-A3B-DFlash-MLX-6bit` draft model's `config.json` had `block_size` nested inside `dflash_config` and `rope_theta` nested inside `rope_parameters`, but `DFlashDraftModelArgs.__init__()` expects both at the top level. This caused DFlash initialization to fail, the model fell back to VLM engine, the runtime signature mismatch triggered an unload/reload cycle, and the cycle repeated indefinitely.

2. **Config fix applied**: Added `"block_size": 16` and `"rope_theta": 10000000` as top-level keys in the draft model's `config.json`. The nested values are preserved for backward compatibility.

3. **MTP weight loading failure (original)**: The Ornith model has a separate `mtp.safetensors` file (453 MB, 46 tensors, 4-bit affine quantized with group_size=64) that was not loaded because:
   - mlx-lm's `load_model()` globs for `model*.safetensors` — `mtp.safetensors` does not match.
   - `model.safetensors.index.json` had zero entries referencing the MTP file.
   - When Lightning MTP is enabled, oMLX's `_has_mtp_weights()` correctly detects MTP weights in the index and attaches the MTPModule, but the weights are never loaded, causing: "missing the mtp.* tensors".

4. **Three original fixes applied for MTP loading**:
   - Renamed `mtp.safetensors` → `model-mtp.safetensors` (matches the glob pattern).
   - Updated `model.safetensors.index.json` weight map: 46 entries changed from `mtp.safetensors` to `model-mtp.safetensors`.
   - Patched the sanitize function in `/Applications/oMLX.app/Contents/Resources/omlx/patches/mlx_lm_mtp/qwen35_model.py` to dequantize pre-quantized MTP weights (4-bit affine with group_size=64) to BF16, stripping quantization metadata that `nn.Linear(bias=False)` layers cannot accept.

5. **oMLX update wiped patches**: The app bundle was updated between sessions, which overwrote the dequantization patch in the sanitize function. The `.biases` tensors from 4-bit affine quantization were no longer being stripped/dequantized, causing "Received 13 parameters not in model" errors for each `.biases` key when MTP was enabled.

6. **Weight file fix (second session)**: Stripped the 13 `.biases` tensors directly from `model-mtp.safetensors` (reducing from 46 to 33 tensors, 453→428 MB). MLX's weight loader accepts packed U32 `.weight` + `.scales` as a native quantized format, but rejects `.biases` when the layer has `bias=False`. This bypassed the need for the sanitize patch.

7. **Dequantization with zero biases → 0% MTP acceptance**: After stripping `.biases` from the file, the dequantization patch (re-applied) used `mx.zeros_like(scales)` as fallback biases. This produced incorrect dequantized weights, collapsing MTP draft acceptance to 0% (all drafts rejected, tok/cycle=1.00, no speedup).

8. **Final fix**: Re-downloaded original `mtp.safetensors` from HuggingFace (46 tensors, 13 `.biases` restored). Dequantization patch now uses the real `.biases` values, producing correct BF16 weights. MTP acceptance recovered to ~50% (tok/cycle=2.50).

   - VLM MTP path: `/Applications/oMLX.app/Contents/Resources/omlx/patches/mlx_vlm_mtp/qwen35_moe_vlm_runtime.py`

## Do Not Repeat / Lessons Learned

1. **MTP dequantization must use real .biases values**: Dequantizing 4-bit affine weights with `mx.zeros_like(scales)` as bias fallback produces incorrect weights (0% MTP acceptance). The biases from the pre-quantized format encode real quantization offset information that is essential for correct dequantization.
2. **Stripping .biases from the file is not a valid long-term fix**: While it "works" (MLX accepts U32 .weight + .scales as native quantized format), it precludes proper dequantization and leaves the model vulnerable to oMLX updates wiping the sanitize patch.
3. **oMLX updates overwrite app bundle patches**: Any oMLX update (Homebrew, auto-update) replaces files in `/Applications/oMLX.app/Contents/Resources/omlx/patches/`. The patches must be re-applied after each update. Consider documenting the patch procedure or creating a reapply script.
4. **Draft model config validation**: When adding a DFlash draft model, verify that its `config.json` has `block_size` and `rope_theta` as top-level keys (not nested in `dflash_config` / `rope_parameters`). This is a known upstream bug in both `funnygeeker` and `z-lab` DFlash models.
5. **Infinite reload loop diagnostic**: The "Runtime settings variant changed" message repeating every 20–25 seconds indicates a signature mismatch where the loaded engine type (VLM/Batched) conflicts with the expected engine type (DFlash). Check whether DFlash initialization is silently failing.
6. **Server restart required for Python edits**: Edits to `.py` files in the app bundle require a full server restart (kill both `omlx-server` and `oMLX` GUI processes) to clear the in-memory bytecode cache (`.pyc` files in `__pycache__/`).
7. **HuggingFace download reliability**: Re-downloading the original `mtp.safetensors` (453 MB) from HuggingFace via `curl` is slow but reliable. Download speed was ~10 MB/s, taking ~45 seconds. Use this as a fallback if the file needs to be restored.
8. **Admin API auth**: The oMLX admin API at port 8001 uses Bearer token auth (API key `958659`) for the `/v1/` endpoints and cookie-based session auth for `/admin/api/` endpoints. Login first via `POST /admin/api/login` with `{"api_key": "..."}` to obtain cookies for admin operations.
