## Established Facts

1. **DFlash infinite reload loop root cause**: The `funnygeeker/Qwen3.6-35B-A3B-DFlash-MLX-6bit` draft model's `config.json` had `block_size` nested inside `dflash_config` and `rope_theta` nested inside `rope_parameters`, but `DFlashDraftModelArgs.__init__()` expects both at the top level. This caused DFlash initialization to fail, the model fell back to VLM engine, the runtime signature mismatch triggered an unload/reload cycle, and the cycle repeated indefinitely.

2. **Config fix applied**: Added `"block_size": 16` and `"rope_theta": 10000000` as top-level keys in the draft model's `config.json`. The nested values are preserved for backward compatibility.

3. **MTP weight loading failure**: The Ornith model has a separate `mtp.safetensors` file (475 MB, 46 tensors, 4-bit affine quantized with group_size=64) that was not loaded because:
   - mlx-lm's `load_model()` globs for `model*.safetensors` — `mtp.safetensors` does not match.
   - `model.safetensors.index.json` had zero entries referencing the MTP file.
   - When Lightning MTP is enabled, oMLX's `_has_mtp_weights()` correctly detects MTP weights in the index and attaches the MTPModule, but the weights are never loaded, causing: "missing the mtp.* tensors".

4. **Three fixes applied for MTP loading**:
   - Renamed `mtp.safetensors` → `model-mtp.safetensors` (matches the glob pattern).
   - Updated `model.safetensors.index.json` weight map: 46 entries changed from `mtp.safetensors` to `model-mtp.safetensors`.
   - Patched the sanitize function in `/Applications/oMLX.app/Contents/Resources/omlx/patches/mlx_lm_mtp/qwen35_model.py` to dequantize pre-quantized MTP weights (4-bit affine with group_size=64) to BF16, stripping quantization metadata that `nn.Linear(bias=False)` layers cannot accept.

5. **Draft model landscape**: On HuggingFace, the only MLX-native DFlash draft model for Qwen3.6-35B is `funnygeeker/Qwen3.6-35B-A3B-DFlash-MLX-6bit` (322 MB, 6-bit, 8 target layer IDs). The official `z-lab/Qwen3.6-35B-A3B-DFlash` (210k downloads) has the same config.json nesting issue and is PyTorch format. The `AEON-7/AEON-DFlash-Qwen3.6-35B-A3B` (904 MB, 5 target layer IDs, kv_heads=4) also works but has a slight kv_heads mismatch with the target (2 kv_heads).

6. **Architecture compatibility**: The funnygeeker 35B draft (`hidden_size=2048`, `num_target_layers=40`, `vocab_size=248320`, `model_type=qwen3`) is compatible with both the unsloth Qwen3.6-35B target and the Ornith-1.0-35B target (`hidden_size=2048`, `num_hidden_layers=40`, `vocab_size=248320`, `model_type=qwen3_5_moe`). oMLX's `is_dflash_compatible()` allows any model with `"qwen" in model_type`.

7. **Server process management**: The oMLX server runs on port 8001 with admin API key `958659`. Admin API uses session cookies (not Bearer tokens). The server was restarted during debugging.

## Key Decisions

1. **Patch draft config rather than disable DFlash**: Instead of disabling DFlash for the affected model (which would resolve the reload loop but lose acceleration), we patched the config.json to supply the missing required fields. This preserves DFlash functionality.

2. **Rename MTP weights file**: Rather than modifying mlx-lm's weight loading glob pattern (which would require patching the installed package), we renamed `mtp.safetensors` to `model-mtp.safetensors` to match the existing `model*.safetensors` pattern. This is simpler, non-invasive, and reversible.

3. **Dequantize MTP weights in sanitize**: Two options existed: (a) modify the MTPModule to use `nn.QuantizedLinear` with matching quantization parameters (4-bit, group_size=64), or (b) dequantize the weights to BF16 in the sanitize function. Option (b) was chosen because it requires no architecture changes to the MTPModule, the MTP head is small (475 MB vs 19 GB main model), and running it unquantized is acceptable.

4. **Funnygeeker 35B draft over AEON draft**: The funnygeeker draft is only 322 MB (vs 904 MB), has 8 target layer monitoring points (vs 5), is MLX-native (6-bit quantized), and its kv_heads=8 matches the target better than AEON's kv_heads=4 (target has kv_heads=2, so neither matches exactly, but the architecture compatibility check passes for both).

## Do Not Repeat / Lessons Learned

1. **Draft model config validation**: When adding a DFlash draft model, verify that its `config.json` has `block_size` and `rope_theta` as top-level keys (not nested in `dflash_config` / `rope_parameters`). The oMLX `DFlashDraftModelArgs` class requires them at the top level.
2. **MTP weight file naming**: `mtp.safetensors` must be renamed to `model-mtp.safetensors` (or match `model*.safetensors` glob) for mlx-lm's weight loader to pick it up.
3. **Admin API authentication**: The oMLX admin API uses session cookies, not Bearer tokens. Login first via `POST /admin/api/login` with `{"api_key": "..."}` to obtain cookies.
4. **Server restart required for Python edits**: Edits to `.py` files in the app bundle require a full server restart (kill both `omlx-server` and `oMLX` GUI processes) to clear the in-memory bytecode cache.
5. **Pre-quantized MTP weights**: MTP weights quantized with 4-bit affine quantization (group_size=64) cannot be loaded directly into `nn.Linear(bias=False)` layers. The sanitize function must dequantize them to BF16.
6. **Infinite reload loop diagnostic**: The "Runtime settings variant changed" message repeating every 20–25 seconds indicates a signature mismatch where the loaded engine type (VLM/Batched) conflicts with the expected engine type (DFlash). Check whether DFlash initialization is silently failing.
7. **Z-lab draft models have the same config bug**: The official `z-lab/Qwen3.6-35B-A3B-DFlash` config.json also nests `block_size` inside `dflash_config` and `rope_theta` inside `rope_parameters`. This is a known upstream issue.
