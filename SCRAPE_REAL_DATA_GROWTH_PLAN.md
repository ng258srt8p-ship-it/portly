## Executive Summary

TripTide currently tracks **~50 sailings** — all of which are **synthetically generated**, not real. Every scraper returns hardcoded data using `genHistory()`, `genCabins()`, and pseudo-random number generators. No actual website scraping occurs, despite Playwright being initialized in the base adapter class.

**This plan replaces all synthetic data with real, scraped cruise information from actual cruise line booking websites, using the existing Jina Reader infrastructure that already exists in `server/services/jinaSync.ts`.**

| Automation | Manual (`tsx run.ts`) | Cloudflare Worker cron (every 4h) |
| Data freshness | Static (set once, never updates) | Continuously refreshed per sailing |

## Part 1: Root Cause Analysis

### 1.1 The Synthetic Data Problem

Every file in `scrapers/` generates fake data:

| File | What It Does |
|------|-------------|
| `scrapers/carnival-corp.ts` | Returns hardcoded Carnival sailings with prices from `genHistory()` and cabins from `genCabins()` |
| `scrapers/additional-lines.ts` | Returns hardcoded NCL, MSC, Disney, Celebrity sailings with synthetic prices |
| `scrapers/princess-cruise-line.ts` | Returns hardcoded Princess sailings with synthetic prices |
| `scrapers/holland-america-line.ts` | Returns hardcoded HAL sailings with synthetic prices |
| `scrapers/royal-caribbean.ts` | Returns hardcoded Royal Caribbean sailings with synthetic prices |
| `scrapers/run.ts` | Orchestrates all adapters, but they all return fake data |

The `SourceAdapter.initialize()` method launches a Playwright browser — but **no adapter ever calls `page.goto()` or `page.content()`**. The browser is started and immediately closed without scraping anything.

### 1.2 What's Actually in Production

The D1 database contains ~50 sailings with:
- `source: "scraper"` (misleading — no real scraping occurs)
- `history[]` arrays generated by deterministic hash functions (same input → same output)
- `cabin_prices` with synthetic multipliers (Inside x0.75, Oceanview x1.0, Balcony x1.65, Suite x3.4)
- No `last_scraped_at` or freshness tracking
- No real price history (only synthetic curves)

### 1.3 The Hidden Real Implementation

`server/services/jinaSync.ts` **already exists** and uses Jina AI Reader to scrape real cruise data:
- Fetches actual HTML from cruise line booking pages
- Parses markdown output for ship names, dates, prices, itineraries
- Upserts to PostgreSQL database

**BUT:** It's limited to `CRUISE_URLS.slice(0, 3)` (line 139) — only 3 of the 56 URLs in `cruiseLineConfig.ts` are used. And it's not connected to the main scraper system at all.

export class RealCarnivalScraper {
  private reader = new JinaReader();
  
  async fetchSailings(): Promise<SailingRecord[]> {
    const urls = [
      'https://www.carnival.com/cruises/breeze',
      'https://www.carnival.com/cruises/mardi-gras',
      // ... all ships from cruiseLineConfig.ts
    ];
    
    const sailings: SailingRecord[] = [];
    for (const url of urls) {
      const result = await this.reader.scrape(url);
      const parsed = parseCarnivalMarkdown(result.markdown, url);
      sailings.push(...parsed);
      await sleep(2000); // Rate limit
    }
    return sailings;
  }
}

#### 3.2 Data Validation Pipeline

Every scraped sailing must pass validation before entering the database:

```typescript
interface ValidationResult {
  valid: boolean;
  errors: string[];
  warnings: string[];
}

function validateSailing(sailing: SailingRecord): ValidationResult {
  const errors: string[] = [];
  const warnings: string[] = [];
  
  // Required fields
  if (!sailing.ship || sailing.ship.length < 2) errors.push('Missing or invalid ship name');
  if (!sailing.sailDate || isNaN(new Date(sailing.sailDate).getTime())) errors.push('Invalid sail date');
  if (!sailing.price || sailing.price <= 0 || sailing.price > 100000) errors.push(`Invalid price: ${sailing.price}`);
  if (!sailing.nights || sailing.nights < 1 || sailing.nights > 60) errors.push(`Invalid duration: ${sailing.nights} nights`);
  
  // Itinerary must have at least 2 ports
  if (!sailing.itinerary || sailing.itinerary.length < 2) warnings.push('Itinerary has fewer than 2 ports');
  
  // Price must be realistic for the cabin type
  if (sailing.cabins) {
    for (const cabin of sailing.cabins) {
      if (cabin.baseFarePerPerson <= 0 || cabin.baseFarePerPerson > 50000) {
        errors.push(`Invalid cabin price for ${cabin.cabinClass}: $${cabin.baseFarePerPerson}`);
      }
    }
  }
  
  return { valid: errors.length === 0, errors, warnings };
}
```

### Phase 4: Automate & Ensure Freshness (Weeks 6-7)

**Goal:** Make data continuously fresh with automated scheduling.

#### 4.1 Cloudflare Worker Cron Job

Set up the existing cron trigger in `workers/wrangler.toml`:

```toml

```

Add a scheduled handler that:
1. Fetches the list of active sailings from D1
2. Groups by cruise line
3. Runs real scrapers for each line (respecting rate limits)
4. Updates prices, adds new sailings, removes sold-out ones

#### 4.2 Data Freshness Tracking

Add to D1 `sailings` table:
```sql
ALTER TABLE sailings ADD COLUMN last_scraped_at TEXT;
ALTER TABLE sailings ADD COLUMN scrape_source TEXT DEFAULT 'jina-reader';
ALTER TABLE sailings ADD COLUMN data_freshness TEXT DEFAULT 'fresh' 
  CHECK (data_freshness IN ('fresh', 'stale', 'archived'));
```

- `fresh`: Scraped within last 24 hours
- `stale`: Last scraped >7 days ago (still shown but with warning)
- `archived`: No longer available (sailing passed or cancelled)

## Part 7: Data Authenticity Guarantee

### "No Fake Data" Policy — Enforced

Every data point displayed to users MUST trace back to a real source:

| Data Type | Source Requirement | Validation Rule |
|-----------|-------------------|-----------------|
| **Sailing existence** | Real cruise line booking website | Must have valid, working booking URL |
| **Price** | Scraped from operator's booking engine | Must be >$50, <$100,000, and match expected range |
| **Itinerary** | From operator's published schedule | Must have >=2 ports with valid names |
| **Ship details** | From operator's published specs | Must match known ship capacity and year |
| **Price history** | Actual price points from repeated scrapes | Must have >=5 data points spanning >=30 days for "90-day low" badge |

### Synthetic Data — Explicitly Banned

The following are **synthetic/fake** and MUST NOT appear in active inventory:
- `genHistory()` output (deterministic hash-based price curves)
- `genCabins()` output (fixed multipliers: Inside x0.75, Balcony x1.65, Suite x3.4)
- `genMultiCabinPriceHistory()` output (synthetic per-cabin trajectories)
- Any data not sourced from a real HTTP request to a cruise line website

### Enforcement Mechanism

```typescript
// In the worker's formatSailing(), add:
if (sailing.scrape_source === 'synthetic' || !sailing.last_scraped_at) {
  // Never show synthetic data as active
  return null; // Skip this sailing entirely
}

// Only include sailings with real, fresh data:
if (sailing.data_freshness === 'archived') {
  return null; // Skip archived sailings from deals list
}
```
